# njin-mail

Multi-tenant webmail client built with Bun. One fixed IMAP/SMTP backend server serves many client domains (tenants) — e.g. `j3company.com`, `jadiweb.id` — each reached through its own webmail hostname (`mail.j3company.com`, `mail.jadiweb.id`) that DNS/proxies to this same app instance. There is no per-account "add mail account" UI: users log in with just their email + password, and the login IMAP attempt itself is the validation.

**Critical constraint**: a user from one tenant domain must never be able to log in through another tenant's webmail hostname (e.g. `support@j3company.com` must be rejected if it tries to log in via `mail.jadiweb.id`).

## Architecture

- **Domain enforcement is per-request, based on the `Host` header**, NOT on `IMAP_HOST`/`SMTP_HOST` (those are one fixed backend, shared by every tenant). See `apps/server/src/lib/tenant.ts`: `getTenantDomainFromHost()` strips a `mail.` prefix from the incoming `Host` header to get the allowed domain; `emailMatchesTenantDomain()` checks the login email's domain against it.
- **No persisted IMAP/SMTP passwords.** Login validates directly against IMAP (`verifyImapCredentials` in `imapClient.ts`); on success the password is encrypted (AES-256-GCM, `lib/crypto.ts`) and kept only in an **in-memory session store** (`lib/sessionStore.ts`, `Map<sessionId, SessionData>`), tied to a session cookie (`njin_sid`, httpOnly). Sessions are lost on server restart by design. The `users` table only stores email/tenantDomain/displayName/timestamps, never a password.
- **Monorepo** (Bun workspaces): `apps/server` (Hono API + `Bun.serve`), `apps/web` (Vite + React + Tailwind + shadcn/ui), `packages/shared` (shared DTO types). Dev: Vite on :5173 proxies `/api` to Hono on :3001. Prod: Hono serves the built `apps/web/dist` as static files with SPA fallback, single process.
- **DB**: SQLite via `bun:sqlite` + Drizzle ORM. Schema: `users`, `folders`, `messages`, `attachments`, `sync_state` — all scoped by `user_id`.

## Gotchas (don't repeat these)

- `drizzle-kit` config (`drizzle.config.ts`) must live **inside `apps/server`**, not the workspace root — at the root it resolves the wrong `drizzle-orm` from a different `node_modules` and fails with "Please install latest version of drizzle-orm".
- Bun does **not** auto-load a `.env` from a parent directory — only from `process.cwd()`. Since the server's cwd is `apps/server`, its scripts (`dev`, `start`, `db:migrate`) run with `--env-file=../../.env` pointing at the root `.env`.
- React Router v7 dropped the `:param?` optional-param syntax — use two separate `<Route>` entries instead (e.g. `/mail` and `/mail/:folderId`).
- Use `@types/bun` (not `bun-types`) as the devDependency, with `"types": ["bun"]` in `apps/server/tsconfig.json`.
- **Local dev tenant bypass**: `mail.jadiweb.id` (the real webmail hostname) is *also* the value of `IMAP_HOST`/`SMTP_HOST` in this dev environment — never add a hosts-file entry pointing that hostname at `127.0.0.1` to test the Host-header tenant check in a browser, it hijacks the server's own outbound IMAP/SMTP connection (broke live email for a bit before this was caught). Instead `.env` sets `DEV_TENANT_DOMAIN=jadiweb.id`, which `resolveTenantDomain()` in `tenant.ts` honors *only* when `NODE_ENV !== "production"` (loud console warning on boot when active) — lets `http://localhost:5173` work directly, no hosts-file tricks needed. Never set `DEV_TENANT_DOMAIN` outside local dev.
- On this Bun version (1.3.14), `bun run --filter apps/server <script>` silently matches **zero** packages ("No packages matched the filter") — the workspace filter needs a `./` prefix: `--filter ./apps/server`. Every root `package.json` script (`dev`, `build`, `start`, `db:generate`, `db:migrate`) was broken by this until fixed; verify with an actual `bun run build && bun run start` from the repo root (not just from inside a workspace dir) after touching these scripts.
- `apps/server/src/app.ts`'s static-file serving (`serveStatic`) resolves its `root` relative to `process.cwd()`, not the module's location — a plain relative string like `"../web/dist"` only works by accident when launched from `apps/server`. It now uses `path.join(import.meta.dir, "../../web/dist")` (Bun-specific `import.meta.dir`) so it's correct regardless of the launch cwd; don't revert to a bare relative string.
- The Bun server binds to `hostname: "127.0.0.1"` explicitly in `index.ts` — it must never listen on all interfaces, since in production it sits behind Caddy on the same host and should never be reachable directly from outside.

**Done & verified:**
1. Repo scaffold (workspaces, Hono server, Vite/React/Tailwind web) — installs, boots, typechecks clean.
2. `bun:sqlite` + Drizzle schema + migrations — verified via seed script.
3. `imapflow`/`nodemailer` Bun-compatibility scripts (`src/scripts/imapTest.ts`, `smtpTest.ts`) — verified against a real `mail.jadiweb.id` test account.
4. Credential encryption (`crypto.ts`) + in-memory session store (`sessionStore.ts`) — unit tested.
5. Hono skeleton with session middleware + prod static serving.
6. Auth API (`POST /api/auth/login|logout`, `GET /api/auth/session`) — verified end-to-end: correct-tenant login succeeds, wrong-tenant `Host` header rejected 401 before IMAP is even attempted, session/logout cookie flow correct.
7. Folder sync (`GET /api/folders`) — `listMailboxes()` in `imapClient.ts` runs IMAP `LIST` with a `statusQuery` (unseen/uidNext/uidValidity); `folderSync.ts` upserts each mailbox into `folders` keyed on the `(userId, name)` unique index. Verified end-to-end against the real `mail.jadiweb.id` test account: all 6 mailboxes synced with correct `specialUse` and live unread counts; re-running the sync updates existing rows (same `id`s) instead of duplicating.
8. Message sync engine (`POST /api/folders/:folderId/sync`) — `fetchNewMessages()` in `imapClient.ts` opens the mailbox and fetches envelope/flags/size/bodyStructure for UIDs above the folder's `sync_state.lastUidSynced`; `messageSync.ts` persists them into `messages` (addresses serialized as JSON, `hasAttachments` derived by walking `bodyStructure` for a `disposition: attachment` node), then advances `sync_state` and the folder's `uidNext`/`uidValidity`. Body text/HTML is intentionally left unfetched here (`bodyFetchedAt` stays null) — deferred to the on-demand fetch in the messages API. Verified end-to-end against the real INBOX: first sync pulled all 12 existing messages with correct envelopes/dates/flags; re-running synced 0 (correct incremental behavior via `lastUidSynced`).
9. Messages API — `GET /api/folders/:folderId/messages` (paginated `limit`/`offset`, ordered by `coalesce(date, internal_date) desc`) lists from the DB only, no IMAP hit. `GET /api/messages/:messageId` reads from DB and, if `bodyFetchedAt` is still null, calls `ensureMessageBody()` (`lib/messageBody.ts`) which fetches the full RFC822 source over IMAP (`fetchMessageSource()` in `imapClient.ts`), parses it with `mailparser`, and persists `bodyText`/`bodyHtml`/`snippet`/`attachments` so later reads are DB-only. DTO mapping (address/flags JSON parsing) lives in `lib/messageDto.ts`. Verified end-to-end: list returned real messages sorted newest-first; detail fetch on an unfetched message pulled and persisted the real body + correct snippet (confirmed via direct DB read, `bodyFetchedAt` set); unknown/foreign message id correctly 404s.
10. Send API (`POST /api/messages/send`) — `lib/smtpClient.ts` sends via `nodemailer` using the session's decrypted password, generating our own `Message-Id` and building the raw RFC822 source with `MailComposer` so the exact same bytes that go out over SMTP are archived. After a successful send, the route best-effort `appendMessage()`s that raw source into the user's `\Sent`-flagged folder (`lib/imapClient.ts`, IMAP `APPEND`) — archive failure doesn't fail the request since the send already succeeded. Optional `replyToMessageId` looks up the original message's `messageId`/`referencesHdr` in the DB and sets `In-Reply-To`/`References` for proper threading. Verified end-to-end against the real account: sent mail was actually delivered (showed up in INBOX on next sync), archived correctly into Sent Items (correct subject/flags), and a reply carried the correct `In-Reply-To` header pointing at the original message's `Message-Id`.

11. Message action endpoints — `POST /api/messages/:id/unread` (removes `\Seen`), `POST /api/messages/:id/flag` (toggles `\Flagged`, returns `{flagged}`), `POST /api/messages/:id/move` (body `{destination: "junk"|"trash"|"archive"}`, resolves target by `specialUse` for junk/trash; for archive, matches/creates a folder literally named "Archive" via IMAP `CREATE` since the server has no `\Archive` special-use folder — orchestration lives in `lib/messageActions.ts`). A move deletes the local DB row for the source location; the destination folder picks the message back up (new UID) on its next open-triggered sync. Verified end-to-end against the real account: unread/flag toggle confirmed via re-sync, move-to-junk and move-to-archive (including auto-created "Archive" folder, which Stalwart happily tagged `\Archive` itself by name) both landed the message in the right place with a fresh UID.

**Frontend** (`apps/web`, Vite + React + TanStack Query, monochrome design, all UI copy in Indonesian):
- **Login** (`pages/LoginPage.tsx`) — generic error message (never distinguishes wrong-password from wrong-tenant), no hostname/tenant hints anywhere in copy (explicit product requirement — this must never read as multi-tenant to the end user).
- **Mail** (`pages/MailPage.tsx`) — 3-pane layout (folder sidebar / message list / detail), folder sync-on-open, mark-as-read on open, client-side search filter over the active folder's loaded messages, and full message actions wired to the milestone 11 endpoints: Reply/Reply All/Forward (open Compose prefilled with quoted HTML + `replyToMessageId` for threading), Belum Dibaca, Tandai (flag), Spam/Hapus/Arsipkan (move), Cetak (`window.print()` + Tailwind `print:` variants to hide chrome and show only the message body).
- **Email HTML rendering** (`components/EmailHtmlView.tsx`) — Thunderbird-style protection: remote images/CSS `url()` blocked by default (banner + "Tampilkan konten" opt-in per message), rendered inside a sandboxed `<iframe sandbox="allow-same-origin allow-popups allow-popups-to-escape-sandbox">` (no `allow-scripts`, so email HTML/CSS is fully isolated from the app and can never execute JS even if DOMPurify sanitization were bypassed), links forced to `target=_blank rel=noopener noreferrer`.
- **Compose** (`components/compose/ComposeWindow.tsx`) — Gmail-style popup (bottom-right small / maximized / minimized), plain-text or Tiptap rich-text mode (toggle), inline link insertion (no `window.prompt`), image upload → `cid:`-embedded MIME inline attachment (extracted from a `data:` preview URI only at send time, never sent as bloated base64-in-HTML), regular file attachments (any type, chips UI, 15MB/10-file limits enforced both client and server side) — all wired to the real `POST /api/messages/send`.
- Attachment download (`GET /api/messages/:id/attachments/:attachmentId`) — re-fetches the raw message over IMAP and re-parses with `mailparser` on demand (attachment bytes aren't persisted in the DB, only metadata) since the earlier gap was purely a missing UI: sent messages always had their attachments correctly archived, `MailPage.tsx` just never rendered the `attachments` list. Verified with a byte-for-byte download check against a real sent attachment.
- Mobile-responsive layout (`md:` breakpoint) — sidebar becomes an off-canvas drawer, list/detail panes show one-at-a-time with a back button, Compose becomes a near-fullscreen bottom sheet, header collapses (search moves into the list panel). Compose's "Tulis" trigger is a floating action button (bottom-right, fixed) rather than a sidebar button, hidden while Compose is already open.
- Backend (auth, folder sync, message sync, messages API, send API, message actions, attachment download) and frontend (login, mail, compose, mobile layout) are functionally complete end-to-end. Not yet built: Settings page (explicitly deferred), message pagination/infinite-scroll beyond the first page.

## Deployment

Target shape: single Linux VPS, app runs as a systemd service (`deploy/njin-mail.service`), Caddy in front as reverse proxy for automatic per-tenant HTTPS (`deploy/Caddyfile`) — chosen because the SQLite file + in-memory session store rule out serverless and multi-instance setups. Full runbook (first deploy, onboarding a new tenant domain, redeploying, backups) is in `deploy/README.md`. Production env template: `deploy/.env.production.example`.
